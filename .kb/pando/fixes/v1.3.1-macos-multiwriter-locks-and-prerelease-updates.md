# v1.3.1: macOS pando.db write hang fixed (go-sqlite-multiwriter v0.1.2) + update check skips prereleases (2026-10-13)

Investigation: [[pando/investigations/2026-10-13-macos-multiwriter-write-hang.md]]. Engine: [[sqlite-multiwriter-engine-v1.3.0]].

## 1. Library go-sqlite-multiwriter v0.1.2 (pushed: commit a0e2372 on main, tag v0.1.2)
- Cause: membership `flock(LOCK_SH)` and the publish/compact/prefill `fcntl` byte locks were on the same `<db>-mwlock`. On macOS and the BSDs both lock kinds share one per-file list with different owners, so every commit's `F_SETLKW` waited forever.
- Fix (`mp.go`):
  - New `separateByteLocks = runtime.GOOS != "linux"` and a `mpState.byteF` field.
  - Outside Linux, byte locks go to `<db>-mwfcntl`. Linux keeps them on `-mwlock`, unchanged, so it stays compatible with v0.1.1 processes.
  - New `closeLocks(remove)` closes and removes both files. Early error paths in `openMP` use it.
  - README updated.
- Tests:
  - `mp_locks_test.go`: `TestByteLockLayoutSuitsPlatform` probes the OS for the flock/fcntl interaction and fails if the layout ignores it; `TestMPCommitWithMembershipHeld` commits with both layouts under a 10 s timeout and checks the lock files are cleaned up.
  - `MW_SEPARATE_BYTE_LOCKS=1` (TestMain) runs the multi-process tests, children included, with the separate layout on Linux.
- Verified on Linux: full suite passes in both layouts. darwin/arm64 vet and test-compile pass. NOT run on a real Mac: the library has no CI.

## 2. Pando changes (jj commit oqyzlssp / git 88ab1bb9, "fix(db,update): ...")
- `go.mod`/`go.sum`: multiwriter v0.1.2. `docs/database.md` mentions `pando.db-mwfcntl`.
- `internal/updatecheck/release.go`:
  - Cause: `detectLatestReleaseManual` listed `/releases` and `selectReleaseForTargets` skipped only drafts, so pre-release v1.3.0 was offered in the WebUI and by `pando update`.
  - Fix: new `stableReleases()` drops nil entries, drafts, `prerelease: true` and semver pre-release tags. `DetectVersion` (explicit `--version` pin) bypasses it.
  - Tests in `release_test.go`.
- Verified: `go build ./...`; tests pass for `./internal/db/...` (multi-process included), `./internal/updatecheck`, `./internal/llm/agent`, `./internal/api` and `./cmd`; `GOOS=darwin` vet of `internal/db` and `internal/updatecheck` passes.

## Release status
- Pushing `main` and tag `v1.3.1` was blocked by the permission classifier; the user has to run it or allow it.
- Pre-existing `.kb/.pmngr` changes (US-0132, EP-0022) were left uncommitted in the working copy.
- After CI publishes: users must close every Pando, update, and reopen. Stale `pando.db-mw*` files from killed processes are replayed by the first opener.
- Mac smoke test still needed: Desktop prompt, TUI, and two processes at once.
