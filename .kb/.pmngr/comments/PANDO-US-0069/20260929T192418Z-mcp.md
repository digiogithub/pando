Implemented 2026-09-29 (uncommitted). Behaviour chosen: Cancel marks the run cancelled and signals it but keeps its entry until the goroutine exits; IsSessionBusy ignores cancelled runs (so a follow-up message goes to Run, not to steering on the dying run); Run/Resume/SummarizeStream register atomically via `acquireRun` and wait up to `cancelledRunWait` (10s) for a cancelled run to unwind, so runs never overlap and the message is not lost; IsBusy (model-switch guard) still counts unwinding runs. Cleanup removes only its own entry (`CompareAndDelete`) and clears steering only if it still owned it. Same for `-summarize`.

First iteration (Cancel keeps session busy) was rejected in review: TUI/ACP route messages to Steer when busy, so a message sent right after Cancel was queued on the dying run and silently dropped.
