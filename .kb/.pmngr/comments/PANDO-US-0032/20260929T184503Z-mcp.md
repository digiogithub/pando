Implemented 2026-09-29 (uncommitted in working copy).

- `agent.runs` WaitGroup tracks `runInternal` goroutines; `waitForRuns()` joins them. Route chosen: the goroutine is owned by a lifecycle the test cancels (`Cancel`) and waits on (`waitForRuns`), stated in comments.
- Real production leak found and fixed: on the panic path `events` was never closed, so `Resume`'s drain goroutine (and any `Run` consumer) blocked forever. Now `defer close(events)` runs on both paths.
- `resume_test.go`: teardown joins runs and scans goroutine dump for leaked `runInternal`/`Resume` goroutines; new `TestCancelledRunGoroutineTerminates`.
- Verified: `go test -race -count=20 ./internal/llm/agent` green; `./internal/api` green; mutation (removing deferred close) makes leak check fail.
- Follow-up (not in scope): `Cancel` deletes the `activeRequests` entry immediately, so a new Run can start while the cancelled goroutine still runs, and the old goroutine's deferred delete can remove the new run's entry.
