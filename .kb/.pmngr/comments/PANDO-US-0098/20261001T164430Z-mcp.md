Implemented (uncommitted). Filter core in `internal/rag/relevance.go` (+ `enricher.go`, `memory_enricher.go`), implementation in `internal/llm/modelrouter/relevance.go`, config in `internal/config/decision_filter.go`, wiring in `internal/app/relevance_filter.go`.

Rules that resolve ambiguous criteria:
- "Max candidates": only the first `MaxCandidates` non-pinned candidates (order code -> kb -> events -> memory) are asked. Candidates beyond the cap, or that cannot fit any request (token budget / 64 KiB body), are KEPT, never dropped unseen, and remain subject to the existing `*MaxChars`/`TotalMaxChars` budgets.
- Fail-open: any error class keeps everything with `Applied=false` and `Reason`=class (`no_router`, `hosted_provider`, `timeout`, ...). A failed batch is kept while other batches still apply (`Applied=true`, `Reason="partial:<class>"`).
- Config deviation: `LocalOnly` is stored INVERTED as `ContextEnrichmentDecisionFilterAllowHosted` (default false = local-only). Viper defaults do not reach the Remembrances struct and every config save re-marshals a raw struct, so a default-true bool would silently flip to false (verified). `RemembrancesConfig.DecisionFilterLocalOnly()` exposes the positive form.
- Pinned memories (scope in `MemoryPinnedScopes`) are never asked nor dropped.

Tests: rag (golden filter-off, filter-on, budgets on filtered set, pinned, nil/hot swap under -race), modelrouter (threshold, 500/timeout/401/malformed/missing/unknown choice/no router, 70 candidates -> 2 requests, cap, oversize kept, partial, hosted skipped), config (defaults, validation, persistence round trip), api (payload + 400 on invalid), app (apply/unset).
