## Early validation: tev1:0.8b on Ollama 0.35.0 (2026-09-30, RTX 4000 SFF Ada)

**Setup**
- 16 developer prompts in English and Spanish.
- 4 routes: `quick_question`, `implementation`, `planning`, `docs_translation`, plus `none`.
- One `choice` question per prompt, using exactly the request shape from PANDO-US-0079.
- The script is a scratch Python benchmark.

**Results**
- **Accuracy: 14/16.**
- **Latency, warm:** p50 65 ms, p95 71 ms. The cold first call (model already on disk) took 78 ms.
- **Routes:**
  - `implementation` p = 0.83–0.96 and `planning` p = 0.92–0.99: very clear.
  - `quick_question` p = 0.64–0.70: correct, but it would **fail a 0.80 threshold**.
  - Short follow-ups ("sí, hazlo", "ok continue", "thanks!") go to `none` with p = 0.71–0.93, so they fall back to the coder model as the epic specifies.
- **Misses:**
  - "translate this paragraph to Spanish…" went to `none` (p 0.75).
  - "write the commit message for these changes" went to `implementation` (p 0.73). This is a **confident misroute above 0.60**.

**Implications**
- A default threshold of **0.60** is about right. 0.80 would drop most quick questions to the coder model.
- The wording of route descriptions matters more than the threshold. The route playground (PANDO-US-0083) and the suggested starter routes need well-worded, concrete descriptions, for example naming "translate" and "commit message" explicitly.
- The API returns **unrounded** float probabilities. The docs' "4 decimal places" applies only to their examples, so the client must not assume rounding.
- Router overhead is under 100 ms, so a `timeoutMs` default of 1500 leaves ample headroom for cold loads.
