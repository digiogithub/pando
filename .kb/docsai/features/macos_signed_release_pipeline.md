# Feature: signed + notarized macOS artifacts in the docsai release

## Date
2026-09-01

## Context
`docsai` (/www/docsai, digiogithub/docsai) is a Rust workspace released with
cargo-dist 0.32 (`dist-workspace.toml`, five targets, shell + PowerShell
installers, `.github/workflows/release.yml` autogenerated and hand-edited).
Its releases already published artifacts and CHANGELOG-derived notes, but the
macOS binaries were unsigned.

## Problem
dist has **no macOS code-signing support** (only `ssldotcom-windows-sign`), and
`dist build` compiles and packages the archive in one command, so there is no
hook between "binary exists" and "binary is inside the tarball".
`github-build-setup` only injects steps *before* the build.

## Solution
A custom pre-publish job, `.github/workflows/sign-macos.yml`, wired in with
`host-jobs = ["./sign-macos"]` in `dist-workspace.toml` (and the matching
`custom-sign-macos` job + `host` dependency in `release.yml`). It:

1. downloads the `artifacts-build-*` workflow artifacts,
2. extracts every `*apple-darwin*.tar.gz` and finds the Mach-O files with
   `file -b` (the archives also contain README/LICENSE),
3. provisions the ephemeral keychain, codesigns (hardened runtime + timestamp)
   and notarizes the binaries via the shared `digiogithub/ci-actions@v1`
   actions,
4. repacks the archives under the same names, refreshes any `<archive>.sha256`
   found in any artifact (dist may place checksums in the local or the global
   artifact),
5. re-extracts and re-checks every binary for a `(runtime)` signature — a
   repack that lost the signature fails the release,
6. re-uploads the three artifacts with `overwrite: true`, so `host` publishes
   the signed files through the download it already does.

Notarization is submit-only: a bare Mach-O cannot carry a stapled ticket, so a
downloaded copy is validated by Gatekeeper's online CDHash check. A `.pkg`
would be needed for offline first-run.

## Files touched
- new: `.github/workflows/sign-macos.yml`, `docs/release-signing.md`
- modified: `dist-workspace.toml` (`host-jobs`), `.github/workflows/release.yml`
  (`custom-sign-macos` job, `host` needs + `if`, hand-edit inventory),
  `README.md` (install section)
- secret `MACOS_SIGNING_BUNDLE` set on digiogithub/docsai (same bundle as pando)

## Coupling to watch
`sign-macos.yml` addresses artifacts by dist's names
(`artifacts-build-local-<target>`, `artifacts-build-global`); adding or renaming
a darwin target in `dist-workspace.toml` needs a matching upload step. The
unpacking side is glob-driven. The job fails loudly when no darwin archive or no
Mach-O is found, so "released unsigned" cannot happen silently.

## Verification
- `actionlint` clean on both workflows, YAML parses, `bash -n` on the run blocks.
- The signing/notarization actions themselves were validated against the real
  Developer ID certificates on mac-mini-de-digio (see the pando feature doc).
- Not yet exercised on a runner: docsai has no tags yet, so the first `0.x.y`
  tag is the real test.
