Pando LLM proxy (internal/llmproxy) fix + Anthropic Messages API (2026-06-17). Full details in KB: pando/features/llm_proxy_model_resolution_and_anthropic.md

ROOT-CAUSE BUG: GET /v1/models listed dynamically-fetched models with RAW ids (gpt-4o), but POST /v1/chat/completions only accepted ids in static models.SupportedModels. Background loop app.RefreshDynamicModels -> models.RefreshProviderModelsForAccount registers dynamic models PREFIXED (openai.gpt-4o, APIModel gpt-4o; work.gpt-4o when >1 account of same type via dynamicModelPrefix). So listed raw ids -> 404.

FIX: resolve.go resolveModel(id)->{model,account} 4 layers (registry/alias NormalizeModelID; reverse APIModel scoped to account; prefix-strip+synthModel; single-account fallback), wired into chat+messages handlers. handlers_models.go list now serves from models.GetAllModels() filtered to configured providers/accounts -> prefixed collision-free ids (static Anthropic/Gemini keep canonical ids); on-demand fallback refreshAccountModels (refresh.go) mirrors RefreshDynamicModels. handleGetModel uses resolveModel.
